## 2. Trust Boundaries

1. **Internet to API Gateway**:
   - Untrusted perimeter. All incoming HTTP requests and WebSocket connections are unverified until validated by `AppValidationPipe` and authenticated by `AuthGuard` or `AdminAuthGuard`.
2. **API Gateway to Application Domain Services**:
   - Semi-trusted internal perimeter. Controllers pass strongly-typed, validated DTOs and verified `AuthenticatedPrincipal` objects.
3. **Application Domain to PostgreSQL & Redis**:
   - Trusted data boundary. All SQL queries use parameterized prepared statements generated by Drizzle ORM. Database credentials have restricted privileges (cannot alter schemas or drop production tables during runtime).
4. **Media Client to Object Storage**:
   - Isolated boundary. The application server never proxies raw image binary streams; clients upload directly to MinIO/S3 using ephemeral presigned PUT URLs with server-generated object keys.

---

## 3. Core Security Controls

- **Authentication**: Passwordless phone OTP, email verification, Google/Apple OIDC, and WebAuthn passkeys. Access tokens expire in 15 minutes; refresh tokens use cryptographic rotation with reuse-detection revocation.
- **Authorization**: Every service verifies entity ownership (`userId === entity.userId`), conversation membership, community role, or staff permissions before performing mutations.
- **Auditing**: Administrative actions and security-critical auth events write immutable records to `admin_audit_logs` and `security_events`.
